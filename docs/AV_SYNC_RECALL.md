# 영상·음성 분리 및 립싱크 경험 검증 메모

공개 사례는 `src/data/cases.ts`의 `av-sync`입니다. 아래는 확인된 경험과 구현을 복원할 때 확인할 항목을 나눈 기록입니다.

## 확인된 경험

- 영상·음성을 한 TS 세그먼트에 담아 hls.js로 재생하던 구조에서 영상 로딩 대기가 소리에도 영향을 주는 현상을 겪었습니다.
- 영상과 음성 파일을 나누고, 브라우저에서도 별도 video/audio 요소로 재생했습니다.
- FFmpeg를 사용하는 VOD·Live 생성 과정에서 영상·음성의 시간 차이를 기록했습니다.
- m3u8에 직접 추가한 서비스용 메타데이터로 이 시간 차이를 전달하고 초기 재생 시점을 맞췄습니다.
- 0.5초 이내로 맞으면 재생 화면을 표시하고, 재생 중 0.5초 수준으로 벌어지면 버퍼링 표시와 보정 후 다시 재생했습니다.
- 정확한 태그명, 단위·부호, 사용한 보정 API, 감시 주기, 동일 경계값 처리와 정량 개선 폭은 미확인입니다.

## 기술적으로 구분할 내용

파일 크기 차이와 재생 타임스탬프 차이는 별개입니다. 영상·음성을 같은 파일에 담는 구조 자체가 소리 지연의 필연적 원인은 아닙니다. 당시 구간 다운로드와 버퍼 정책을 확인해야 합니다. 분리해도 공유하는 네트워크와 영상 버퍼 부족은 남으며, 전체 바이트 수가 자동으로 줄어드는 것은 아닙니다.

HLS는 영상·별도 오디오 플레이리스트를 연결하는 구성을 지원하지만, 브라우저에서 반드시 별도 video/audio 요소를 써야 하는 것은 아닙니다. 이번 서비스의 두 요소 구성과 표준적인 한 요소의 다중 트랙 재생을 구분합니다.

커스텀 m3u8 메타데이터는 서비스의 파싱·보정 로직과 함께 동작한 계약입니다. hls.js가 알 수 없는 임의의 태그를 자동으로 립싱크 보정값으로 해석한다고 설명하지 않습니다. `PROGRAM-DATE-TIME`은 날짜·미디어 시간의 매핑이며 임의의 오차 보정 전용 태그가 아닙니다. 자막용 `X-TIMESTAMP-MAP`과도 혼동하지 않습니다.

미디어 PTS, 요소의 currentTime, 실제 화면·오디오 출력 시각은 서로 다른 관찰값입니다. 두 currentTime은 동일한 원점·단위로 해석할 수 있을 때 비교 의미가 있습니다. 서로 다른 소스에서 0부터 시작한 시각이 같다고 실제 장면까지 같은 것은 아닙니다.

초기 오프셋은 시작 기준이고 재생 도중 새로 생긴 드리프트는 현재 상태입니다. 저장한 오프셋만 계속 적용한다고 모든 드리프트가 해소되지는 않습니다. seek·화질 전환·한쪽 대기·라이브 재연결에서 다시 확인해야 합니다.

0.5초는 당시 서비스의 상태 전환 기준입니다. 보편적인 지각 허용 기준이나 실측 오차 상한으로 쓰지 않습니다. 0.5초에서 재개·대기를 동시에 판정하지 않도록 실제 비교 연산을 확인해야 합니다. 공개 의사코드는 경계를 설명하기 위해 재개 < 0.5 / 대기 >= 0.5로 분리했으며 당시 구현을 복원한 코드는 아닙니다.

## 구현을 떠올릴 단서

| 확인할 항목 | 확인할 내용 |
|---|---|
| 커스텀 태그 | 실제 m3u8 원문, 메타데이터의 단위·부호·유효 구간·버전 |
| 생성 파이프라인 | FFmpeg 입력/출력 타임스탬프와 메타데이터를 추가한 스크립트·서버 로직 |
| 시간 차이 정의 | 예: 오디오와 영상의 시작 PTS 차이인지, 특정 장면 기준의 보정값인지 |
| 보정 기준 | 영상·음성 중 어느 쪽을 기준으로 맞췄는지, 공통 시간 원점은 무엇인지 |
| 실제 보정 방법 | currentTime 탐색, 타임스탬프 보정, playbackRate 조정 등 중 실제 사용한 것 |
| 재생 제어 | 화면만 숨겼는지, 한쪽/양쪽을 일시정지했는지, 재개 때 두 요소가 준비됐는지 |
| 비동기 완료 | seeked·canplay·play Promise 완료/거절을 어떻게 처리했는지 |
| 반복 방지 | 보정 중 중복 실행, 재개 경계의 반복 진입, 타임아웃·최대 재시도 정책 |
| Live | 재연결, 타임스탬프 불연속, 슬라이딩 윈도우 밖으로의 탐색 처리 |

위의 후보 구현과 개선책을 모두 당시 수행한 것으로 기록하지 않습니다. 시간 차이 값과 별도 요소 사용까지 확인된 사실이며, 실제 보정 방식은 코드 대조가 필요합니다.

## 측정 기록 틀

- 같은 네트워크·파일에서 분리 전후 음성 요청 완료와 실제 소리 시작 시각을 따로 기록합니다.
- 실제 대응하는 영상·소리(클랩·플래시 등)로 A/V 출력 차이를 확인합니다.
- 초기 재생, 영상 지연, 음성 지연, 탐색, 화질 전환, 재연결 조건을 구분합니다.
- 오차 분포와 재동기화 횟수·복구 시간, 화면·음성 중 어느 것이 대기했는지 적습니다.
- 제공되지 않은 개선 수치와 실제 사용하지 않은 태그·FFmpeg 옵션은 만들지 않습니다.
